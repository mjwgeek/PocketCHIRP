# PocketCHIRP Community Driver Catalog

This directory is the source of truth for PocketCHIRP's optional community-driver catalog.

- `community-drivers.json` contains **approved** entries which PocketCHIRP may offer to users.
- `candidates.json` is generated by GitHub Actions and is **review-only**.
- `sources.json` controls which repositories and GitHub searches the discovery job watches.

## Security model

Discovery never promotes or installs executable Python automatically. A candidate must be manually reviewed before it is copied into `community-drivers.json`. Approved entries include the exact upstream download URL and SHA-256 of the reviewed file. PocketCHIRP verifies the SHA-256 and re-checks the approved manifest before loading or installing a community driver.

## Catalog URL

PocketCHIRP fetches the approved catalog from:

`https://raw.githubusercontent.com/mjwgeek/PocketCHIRP/main/community/community-drivers.json`

The review-only discovery feed is:

`https://raw.githubusercontent.com/mjwgeek/PocketCHIRP/main/community/candidates.json`

## Discovery

The workflow `.github/workflows/discover-community-drivers.yml` runs weekly and can also be started manually from the GitHub Actions page. It scans configured open CHIRP pull requests and GitHub repository searches for likely CHIRP driver Python files, fingerprints them, extracts visible vendor/model metadata, versions driver families, and refreshes `candidates.json`.

To suppress a known unwanted result, add its repository to `ignoredRepositories`, or its `owner/repo#PR` key to `ignoredPullRequests` in `sources.json`.

## Approving or removing a driver

Use **Actions → Manage Community Driver Approval → Run workflow**.

1. Choose `approve` or `remove`.
2. Paste the exact `candidateKey` from `community/candidates.json`. Multiple keys may be comma-separated.
3. Optionally add a testing/review note.
4. Run the workflow.

For approval, the workflow copies the exact discovered candidate metadata into `community-drivers.json`, preserves the discovered download URL and SHA-256, marks the entry approved, records the approval time, increments the catalog revision, and commits the result. Re-running approval for an already-approved candidate refreshes its metadata; if its SHA-256 is unchanged, the original approval timestamp is preserved.

For removal, the matching approved entry is removed from `community-drivers.json` and the catalog revision is incremented. Removal does not delete the candidate from the discovery feed.

The same operation can be run locally with `scripts/manage_community_approvals.py`.
